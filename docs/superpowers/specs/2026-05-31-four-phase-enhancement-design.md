# 清茫微记四阶段功能增强设计文档

## 概述

本文档描述清茫微记后续功能增强的总体设计。设计范围基于当前项目已有能力，覆盖已接纳的改进功能与新增功能，并按四个阶段逐步推进：质量基线与错词闭环、学习体验增强、词汇管理能力增强、数据洞察与激励系统。

本设计优先遵循现有架构边界：页面负责展示与交互，Provider 管理可观察状态，Repository 封装数据访问，Service 承担跨实体业务流程，DIContainer 管理长期依赖。新增功能应尽量复用现有学习流程、统计能力、词库数据、错词服务、备份恢复和 Fluid UI 组件，避免一次性重写核心流程。

## 背景与目标

清茫微记当前已经具备完整的单词学习应用基础：词库管理、学习与复习、SM-2 调度、S-MARS 会话掌握度、错词本、学习统计、备份恢复、TTS 发音、在线释义、深浅色主题和中英文界面。后续增强的核心目标不是重新搭建应用，而是在现有基础上形成更完整的学习闭环。

### 总体目标

1. 补齐当前已有但未完成的关键功能，尤其是错词专项复习。
2. 清理历史 analyzer 问题，降低后续开发成本。
3. 建立可复用的指定单词列表学习入口，为错词、收藏夹、自定义单词集等专项学习提供统一基础。
4. 引入学习计划、提醒和报告，提升每日使用频率和长期坚持动力。
5. 增强搜索、收藏和自定义词集能力，让用户能管理自己的词汇资产。
6. 完善成就与周期报告，让用户看到长期进步和薄弱点。

### 非目标

1. 本轮设计不引入账号系统和云同步。
2. 本轮设计不重写现有数据库架构，只在需要时通过迁移新增表或字段。
3. 本轮设计不替换现有 Provider 架构。
4. 本轮设计不要求一次性实现全部功能，而是作为阶段化实施蓝图。

## 当前现状与问题

### 已具备能力

1. 首页已有学习、复习、继续学习、词库切换等入口。
2. 学习流程已经支持学习记录、复习调度、错词收集、学习总结和 S-MARS 会话掌握度。
3. 词库页支持内置词库导入、自定义词库创建、批量导入、批量删除和进度展示。
4. 统计页已有今日建议、词汇量、连续学习、热力图、复习趋势、复习预测和掌握阶段分布。
5. 设置页已有主题、语言、学习数量、发音、词典、备份、恢复、导入和清空数据能力。
6. 错词页已有错词列表、错误次数、批量选择、标记掌握和词典查看。
7. 项目已经有测试基础，覆盖复习调度、学习限制、模型、翻译、今日建议和会话掌握度等纯逻辑。

### 主要问题

1. 错词专项复习入口仍为占位提示，错词本尚未形成完整学习闭环。
2. 部分历史 analyzer warning/info 尚未清理，影响后续维护。
3. 学习页、词库页等文件仍偏大，部分 UI 与业务流程耦合较重。
4. 本地通知服务当前是简化实现，尚未形成真正的复习提醒。
5. 学习进度保存粒度较粗，未来无法直接支撑错词、收藏夹、自定义词集等多来源学习恢复。
6. 错误处理尚未完全统一，部分页面仍直接使用 SnackBar 或重复创建 Service。
7. 搜索、收藏、自定义词集、周期报告等能力尚未形成体系。

## 总体方案

### 分阶段策略

后续工作拆分为四个阶段：

1. 阶段一：质量基线与错词闭环。
2. 阶段二：学习体验增强。
3. 阶段三：词汇管理能力增强。
4. 阶段四：数据洞察与激励系统。

四个阶段之间存在依赖关系。阶段一先稳定项目质量并抽象专项学习基础；阶段二基于稳定学习流程建设计划与提醒；阶段三复用专项学习入口拓展收藏夹和自定义词集；阶段四基于前面沉淀的数据生成成就和周期报告。

### 核心架构原则

1. 新增业务数据访问优先通过 Repository 暴露，不让页面直接操作 DatabaseService。
2. 新增跨实体流程放入 Service，例如专项学习编排、计划生成、报告生成、通知调度。
3. 需要 UI 响应的长期状态放入 Provider，例如学习计划、收藏夹摘要、通知设置。
4. 学习页不应关心单词来源，只接收统一的学习会话输入。
5. 错词、收藏夹、自定义词集、搜索结果都应能复用同一套指定单词列表学习入口。
6. 所有新增功能都应兼容现有深浅色主题、中英文翻译和 Fluid UI 风格。

### 建议新增的核心抽象

#### StudyEntry / StudySource

用于描述一次学习的来源。

可能的来源包括：

1. 普通新词学习。
2. 到期复习。
3. 错词专项复习。
4. 收藏夹专项学习。
5. 自定义单词集学习。
6. 搜索结果临时学习。
7. 学习计划任务。

#### StudySessionRequest

用于向学习流程传递统一参数。

建议字段：

| 字段 | 说明 |
|---|---|
| source | 学习来源 |
| wordBookId | 关联词库，可为空 |
| wordIds | 指定单词列表 |
| isReview | 是否按复习模式处理 |
| studyMode | 初始学习模式 |
| title | 会话标题 |
| allowProgressSave | 是否允许保存进度 |
| progressKey | 进度保存键 |

#### SpecializedStudyService

用于把错词、收藏夹、自定义词集等来源转换为 StudySessionRequest。

职责：

1. 获取指定来源的单词 ID。
2. 应用排序策略，例如高频错词优先。
3. 创建学习会话请求。
4. 在学习完成后回写来源状态，例如错词强度降低、收藏夹学习次数增加。

## 阶段一：质量基线与错词闭环

### 目标

阶段一的目标是先把当前项目质量拉回稳定状态，并完成最明显的未完成能力：错词专项复习。该阶段完成后，错词本应从“记录错误”升级为“发现薄弱词、专项训练、根据表现调整状态”的闭环。

### 功能范围

#### 1. 清理 analyzer 剩余问题

按照当前交接文档记录的顺序处理历史问题：

1. 清理 pre_study_screen.dart 中未使用字段。
2. 处理不再使用的展示页面或遗留 UI 文件。
3. 替换 Flutter 已废弃 API。
4. 清理 dead code、未使用导入、未使用变量和风格类 lint。
5. 每个文件处理后运行定向 analyze，最后运行全项目 analyze。

验收标准：

1. `flutter analyze` 不再出现历史遗留问题，或剩余问题有明确记录和原因。
2. 不改变现有用户可见行为。
3. 不删除仍被主流程使用的页面和组件。

#### 2. 完成错词专项复习

当前错词页已有专项复习按钮，但实际只是提示功能开发中。阶段一需要实现：

1. 点击专项复习进入学习流程。
2. 非选择模式下复习全部错词。
3. 选择模式下复习选中的错词。
4. 错词按错误次数和最近错误时间排序，高频高近因优先。
5. 如果错词为空，保持当前空状态提示。
6. 学习完成后回到错词页刷新数据。

建议交互：

1. 错词页顶部保留专项复习按钮。
2. 用户未选择单词时，按钮默认复习全部错词。
3. 用户已选择单词时，按钮复习选中错词。
4. 进入学习前可弹出底部面板选择练习模式：回忆、拼写、听力或选择题。

#### 3. 错词强化训练基础版

在错词专项复习基础上增加强化规则：

1. 答错或查看答案后增加错词强度。
2. 答对后降低错词强度。
3. 连续掌握达到阈值后，可自动移出错词本或提示用户确认移出。
4. 错词详情展示错误次数、最近错误时间和掌握状态。
5. 完成页展示本次错词复习结果：复习数量、答对数量、仍需强化数量、建议移出数量。

建议初始规则：

| 行为 | 状态变化 |
|---|---|
| 答错 | 错误次数 +1，最近错误时间更新 |
| 查看答案 | 计为薄弱表现，保留在错词本 |
| 一次答对 | 降低强化优先级 |
| 连续 3 次专项复习答对 | 建议移出错词本 |

#### 4. 统一错误处理

把重复的 SnackBar 和错误提示逐步迁移到 ErrorHandler。

范围：

1. 错词页加载失败、删除失败、标记掌握失败。
2. 学习流程保存失败、发音失败、释义加载失败。
3. 词库导入、备份恢复等重复提示。

验收标准：

1. 常见错误展示用户友好文案。
2. 技术异常不直接暴露给普通用户。
3. 调试日志只保留对开发有价值的信息。

#### 5. 减少 UI 中直接创建 Service

将频繁使用或具有状态的 Service 纳入 DIContainer 或 Repository。

优先对象：

1. WrongWordService。
2. NotificationService。
3. 后续新增的 SpecializedStudyService。

验收标准：

1. 页面优先通过 `context.read<DIContainer>()` 或 Provider 获取依赖。
2. 不在页面中重复初始化同一 Service。
3. 新增方法便于单元测试。

#### 6. 增强学习进度保存

将当前进度保存扩展为可支持多来源学习。

建议能力：

1. 普通学习、复习、错词专项学习可保存独立进度。
2. 保存当前来源、当前索引、剩余单词、学习模式和更新时间。
3. 首页继续学习可展示来源标题，例如“继续错词专项复习”。
4. 恢复时如果单词已不存在，应自动过滤并继续。

### 测试计划

1. 错词排序逻辑单元测试。
2. 错词连续答对后建议移出逻辑测试。
3. 多来源学习进度裁剪逻辑测试。
4. 错词专项复习入口 Widget 或流程测试。
5. `flutter analyze` 全项目检查。

### 阶段一验收标准

1. 错词页专项复习不再显示“功能开发中”。
2. 可复习全部错词和选中错词。
3. 错词复习完成后错词状态会根据表现变化。
4. 学习进度可区分普通学习和错词学习。
5. 全项目 analyzer 状态清晰且可维护。

## 阶段二：学习体验增强

### 目标

阶段二的目标是提高用户每日使用动力，让应用从“可学习”升级为“会安排学习”。核心是学习计划、本地通知、首页任务和计划进度展示。

### 功能范围

#### 1. 学习计划系统

支持用户基于词库和目标日期创建学习计划。

基础能力：

1. 选择一个或多个词库作为计划范围。
2. 设置目标日期或每日新词量。
3. 自动估算每日新词任务。
4. 根据到期复习压力给出提醒。
5. 首页展示今日计划进度。
6. 统计页展示计划完成度。

建议计划类型：

| 类型 | 说明 |
|---|---|
| 固定每日量 | 用户指定每天学习多少新词 |
| 固定截止日 | 用户指定目标日期，系统计算每日任务 |
| 考试目标 | 基于 CET-4、CET-6、考研、TOEFL、SAT 等词库生成计划 |

#### 2. 本地通知提醒

将当前简化的 NotificationService 完善为真实提醒服务。

能力：

1. 设置每日提醒时间。
2. 仅在有待复习或未完成计划时提醒。
3. 支持关闭提醒。
4. 支持修改提醒时间。
5. 点击通知后进入应用首页或复习入口。

设置项：

1. 是否启用提醒。
2. 提醒时间。
3. 提醒条件：有待复习、计划未完成、两者都提醒。

#### 3. 首页今日任务升级

首页展示从“当前词库状态”升级为“今日学习任务中心”。

建议内容：

1. 今日新词任务。
2. 今日复习任务。
3. 当前计划进度。
4. 错词强化建议。
5. 一键开始今日任务。
6. 继续未完成任务。

#### 4. 每日任务完成反馈

完成今日任务后展示反馈：

1. 今日完成率。
2. 新学单词数。
3. 复习单词数。
4. 错词减少数量。
5. 连续学习天数。
6. 明日预计复习压力。

### 建议数据模型

#### StudyPlan

| 字段 | 说明 |
|---|---|
| id | 计划 ID |
| name | 计划名称 |
| wordBookIds | 关联词库 |
| targetDate | 目标日期 |
| dailyNewTarget | 每日新词目标 |
| status | 进行中、暂停、完成 |
| createdAt | 创建时间 |
| updatedAt | 更新时间 |

#### DailyTaskSnapshot

| 字段 | 说明 |
|---|---|
| date | 日期 |
| planId | 计划 ID |
| targetNewWords | 目标新词 |
| targetReviewWords | 目标复习 |
| completedNewWords | 已完成新词 |
| completedReviewWords | 已完成复习 |
| completedAt | 完成时间 |

### 涉及文件与模块

| 模块 | 说明 |
|---|---|
| `lib/screens/home_screen.dart` | 今日任务中心 |
| `lib/screens/settings_screen.dart` | 通知设置、计划入口 |

### 测试计划

1. 目标日期到每日任务量的计算测试。
2. 今日任务完成率计算测试。
3. 通知条件判断测试。
4. 计划暂停、恢复、完成状态测试。
5. 首页任务卡片基础 Widget 测试。

### 阶段二验收标准

1. 用户可以创建学习计划。
2. 首页可以看到今日任务与计划进度。
3. 本地通知可以按设置提醒。
4. 完成学习后计划进度会更新。
5. 统计页可以展示计划完成度。

## 阶段三：词汇管理能力增强

### 目标

阶段三的目标是增强用户对单词资产的组织能力。搜索不再只是查词，收藏夹和自定义单词集不再只是列表，而是可以进入专项学习的词汇管理系统。

### 功能范围

#### 1. 单词搜索增强

在现有搜索基础上增加：

1. 模糊搜索。
2. 按释义搜索。
3. 按例句搜索。
4. 按词库筛选。
5. 搜索历史。
6. 最近查看。
7. 从搜索结果进入单词详情。
8. 从搜索结果加入收藏或自定义词集。

搜索结果排序建议：

1. 完全匹配优先。
2. 前缀匹配其次。
3. 词形相近再次。
4. 释义和例句命中最后。

#### 2. 收藏夹

收藏夹用于用户主动收集重要单词。

能力：

1. 学习页一键收藏当前单词。
2. 单词详情页收藏或取消收藏。
3. 搜索结果收藏。
4. 收藏列表查看。
5. 收藏夹专项学习。
6. 收藏备注。
7. 收藏分组。

#### 3. 自定义单词集

自定义单词集用于用户建立专题词表。

能力：

1. 创建单词集。
2. 从搜索结果加入单词。
3. 从收藏夹加入单词。
4. 从错词本加入单词。
5. 从学习页加入单词。
6. 单词集排序、重命名、删除。
7. 单词集专项学习。

#### 4. 复用专项学习入口

收藏夹和自定义单词集不单独实现学习页，而是复用阶段一建立的 StudySessionRequest 和 SpecializedStudyService。

来源映射：

| 来源 | 学习入口 |
|---|---|
| 错词本 | 错词专项复习 |
| 收藏夹 | 收藏夹专项学习 |
| 自定义词集 | 词集专项学习 |
| 搜索结果 | 临时列表学习 |

### 建议数据模型

#### FavoriteWord

| 字段 | 说明 |
|---|---|
| id | 收藏 ID |
| wordId | 单词 ID |
| groupName | 分组名称 |
| note | 备注 |
| createdAt | 收藏时间 |
| lastStudiedAt | 最近学习时间 |

#### CustomWordSet

| 字段 | 说明 |
|---|---|
| id | 单词集 ID |
| name | 名称 |
| description | 描述 |
| createdAt | 创建时间 |
| updatedAt | 更新时间 |

#### CustomWordSetItem

| 字段 | 说明 |

## 阶段四：数据洞察与激励系统

### 目标

阶段四的目标是提升长期学习反馈，让用户知道自己学了什么、哪里薄弱、下周应该怎么安排。该阶段包括成就系统完善、周报、月报、高频错词、薄弱词库和学习建议。

### 功能范围

#### 1. 成就系统完善

现有统计页已有成就中心入口。后续可以扩展成可维护的成就定义系统。

成就分类：

1. 连续学习类。
2. 累计学习类。
3. 复习完成类。
4. 错词清理类。
5. 收藏整理类。
6. 计划完成类。
7. 搜索探索类。

建议成就示例：

| 成就 | 条件 |
|---|---|
| 初次启航 | 完成第一次学习 |
| 三日坚持 | 连续学习 3 天 |
| 七日习惯 | 连续学习 7 天 |
| 百词入门 | 累计学习 100 词 |
| 错词清道夫 | 移出 50 个错词 |
| 计划执行者 | 连续 7 天完成计划 |
| 收藏整理者 | 收藏 100 个单词 |

#### 2. 每周学习报告

每周报告展示上一周表现。

内容：

1. 新学单词数。
2. 复习单词数。
3. 学习天数。
4. 完成计划天数。
5. 平均正确率。
6. 高频错词 Top 10。
7. 薄弱词库。
8. 下周复习压力预测。
9. 下周建议。

#### 3. 月度学习报告

月度报告展示长期趋势。

内容：

1. 月度累计学习量。
2. 月度复习量。
3. 连续学习最长天数。
4. 词汇掌握阶段变化。
5. 计划完成率。
6. 错词数量变化。
7. 收藏和自定义词集增长。
8. 月度建议。

#### 4. 高频错词排行

基于错词错误次数、最近错误时间和专项复习表现生成排行。

排序因素：

1. 错误次数。
2. 最近错误时间。
3. 最近专项复习是否答错。
4. 是否多次查看答案。

#### 5. 薄弱词库分析

按词库聚合：

1. 未学比例。
2. 到期复习比例。
3. 错词比例。
4. 低掌握度单词比例。
5. 计划滞后程度。

#### 6. 学习建议生成

建议不依赖外部 AI，先基于规则生成。

规则示例：

| 场景 | 建议 |
|---|---|
| 到期复习过多 | 降低明日新词量，优先清理复习 |
| 错词增长过快 | 增加错词专项训练 |
| 连续学习中断 | 降低每日目标，恢复节奏 |
| 某词库薄弱 | 安排该词库专项复习 |
| 计划提前 | 可适度增加每日新词 |

## 数据库与迁移策略

### 原则

1. 每阶段只新增必要表或字段。
2. 新增表优先保持独立，避免破坏现有 review_records、words、word_books 等核心表。
3. 迁移时使用 `CREATE TABLE IF NOT EXISTS` 和幂等索引创建。
4. 备份恢复需要同步支持新增表。
5. 数据库版本升级后必须补充迁移测试或至少手动验证。

## UI 与交互原则

1. 所有新页面使用现有 FluidBackground、FluidCard、FluidButton、FluidDialog 等组件。
2. 继续支持深色和浅色模式。
3. 新增文案必须加入 Translations，保持中英文一致。
4. 列表类页面支持空状态、加载状态、错误状态。
5. 涉及删除、清空、恢复等高风险操作必须二次确认。
6. 首页只展示最重要的今日动作，避免变成信息堆叠页。
7. 统计页优先展示洞察摘要，详细报告通过二级页面展示。

## 错误处理与安全约束

1. 所有文件导入、备份恢复继续保留大小、格式和版本校验。
2. 新增备份字段时必须兼容旧备份文件。
3. 网络词典、发音、通知权限失败不能阻断学习主流程。
4. 数据库异常应通过 ErrorHandler 展示友好提示。
5. 不记录或展示用户本地路径中的敏感信息。
6. 通知权限只在用户开启提醒时请求。

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 范围过大 | 开发周期拉长，功能互相阻塞 | 严格按四阶段推进，每阶段可独立验收 |
| 学习流程耦合过重 | 错词、收藏夹、计划都难以复用 | 先抽象 StudySessionRequest 和专项学习服务 |
| 数据库迁移出错 | 用户数据风险 | 迁移前支持备份，迁移逻辑保持幂等 |
| 首页信息过载 | 用户不知道该点哪里 | 首页只保留今日最重要任务和继续学习入口 |
| 报告计算变慢 | 统计页卡顿 | 报告按需生成并缓存，重计算放到异步流程 |
| 通知权限差异 | 不同平台行为不一致 | 先以 Windows 和移动端可用能力为主，失败不阻断主流程 |
| 新增文案遗漏 | 中英文界面不一致 | 每个功能 PR 同步更新 Translations 和测试 |
